---
name: qz-setup
description: Set up QualiZeal AI-DLC in one pass - plan, usage reading, packages and projects folder - or check it, or write the rollout pack for an organisation admin
argument-hint: "[easy|doctor|usage|plan|org|install|projects|engine|workspace|tools|tokens|github-agent]"
disable-model-invocation: true
---

| Typed | Do |
|---|---|
| `easy` (default) | One pass for someone new. 1. `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup detect`; show its lines as they are. 2. If the plan is not stated, ask which one (Pro, Max, Ultra, Team standard, Team premium, Enterprise, API key) and run `qz.py setup plan <plan>`. 3. If the plan reports usage (Pro, Max, Ultra), this is Claude Code on a laptop and the usage reading is off: run `qz.py setup statusline`, show the change it prints, and run it with `--yes` only after the person agrees. 4. Missing Python packages: the `install` row. 5. No projects folder: the `projects` row. 6. End with the doctor's Result line. In the Claude app's chat only the skills run: say so in one line, and that Cowork or Claude Code adds the hooks, agents and tools. |
| `usage` | `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup statusline`: show what it would change, ask, then run with `--yes`. If another status line is set, it stays unless the person says replace (`--replace`). |
| `plan` | Ask which plan, then `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup plan <plan>` (pro, max, ultra, team-standard, team-premium, enterprise or api). |
| `org` | For an organisation's admin. Ask the marketplace repository (default `qualizeal-aicoe/Qualizeal_AIDLC_For_InHouse`), the plan (team-standard, team-premium or enterprise), the default model (sonnet unless they say) and whether Fable is allowed (no unless they decide who pays for it). Run `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup org --repo <owner/name> --plan <plan> [--default opus] [--fable]`. It writes `managed-settings.json` and `ROLLOUT.md` to the workspace's `_studio/org-rollout` folder. Show the five steps of ROLLOUT.md in five lines. The organisation settings themselves are the admin's clicks: never change them for them. |
| `doctor` | Call the `doctor` tool and show its output as it is. If the tools are not listed, run `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" doctor` (the launcher finds Python on Windows, macOS and Linux and says so plainly when there is none). |
| `install` | Run `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup deps`: it prints the one pip command for the Python it found (openpyxl, python-docx, python-pptx, lxml, pypdf, playwright, pillow). Show it; run it with `--yes` after the person agrees. The browser checks use the laptop's Chrome or Edge; only if neither is installed, also install Playwright's Chromium. LibreOffice (slide previews) and ffmpeg (MP4 and GIF walkthroughs) are optional: the doctor says which are missing. |
| `projects` | Call `project_status`. It says where the local projects folder is (`D:\New_Projects` on Windows when drive D exists, otherwise `New_Projects` in the home folder; `QZ_WORKSPACE_ROOT` or `~/.qz/workspace.json` changes it) and lists the projects. Offer `project_new` for the first one. |
| `engine` | Run `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup engine` and show the one command it prints; the person runs it or says yes to you running it. It installs AWS AI-DLC 2.10.0 from AWS's own release with its checksum check. |
| `workspace` | Run `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup workspace` in this folder: copies the AWS AI-DLC workspace and QualiZeal guardrails in, never overwriting a file that exists, and shows the 14 AWS agents under their QualiZeal names (QZ Architect, QZ Developer and so on). |
| `tools` | `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" tools` shows the profile; with a name (`all`, `lean`, `sales`, `delivery`) run `qz.py tools set <name>` after the person agrees. It decides how many tools a session lists, applies from the next session, and only saves tokens where the app loads every tool up front. |
| `github-agent` | `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" setup github-agent` shows what it writes; with `--yes` after the person agrees it writes `.github/workflows/qz-agent.yml`. Then give the five website steps of the Studio's `docs/GITHUB-AGENT.md` (token, two secrets, the Claude GitHub App) in five lines, and offer `/qz-aidlc:qz-publish` for the pull request. |
| `tokens` | `uv run -q --no-project --python ">=3.11,<3.14" python -I -B -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/qz.py" tokens` and show the output as it is: the context the Studio costs before any work, this run by stage, the largest tool results, what to do next. |

Then: `/plugin` > qz-aidlc > Configure for the GitHub token, Atlassian site, e-mail and token, and the pricing workbook path. Tokens go to secure storage, never into chat. End with the doctor's Result line.
