# Bid lane · proposal deck, RFP or discovery answers, SOW, pricing

Delegate drafting to the `qz-bid-writer` agent and architecture to `qz-solution-architect`; keep this conversation for decisions.

1. **Brief** (`stage brief`). Collect: client, industry, the ask (proposal, RFP response, discovery answers, SOW), deadline, audience and what each stakeholder cares about, decisions needed, constraints, commercial model (T&M or fixed). Read the RFP or notes the person gives you through a sub-agent and bring back a one-page brief. Ask what is missing, one question at a time.
2. **Solution** (`stage solution`). `qz-solution-architect` answers Problem → Requirements → Architecture → Implementation strategy → PoC/MVP → Production path, challenges weak requirements, and names where AI is not needed. `kf_search` (purpose `recommend`) for comparable QualiZeal work; describe it anonymously ("a global airline"), never by client name, and never claim reuse: say what we will build for them.
3. **Pricing** (`stage pricing`). Build the staffing plan JSON (roles exactly as `price_roles` lists them; months as `{"from":1,"to":6,"fte":1}`). **Every role is offshore**: leave `location` out and it defaults to Offshore. Put one person onshore only when the client has asked for it, only for a PMO or manager role, and mark that line `"client_requested_onshore": true`; ask the person before adding it. Run `price_run`; report the client totals, the staffing check and the PASS/REVIEW margin check. Never ask for or show cost, pay rate or margin. Warnings that Excel prices a line at 0 (its lookups stop at Input row 61, which misses most offshore roles) or that a rate sits far under the catalogue median go to the person as one line each. Offer `price_patch` with `fix_lookup: true` so finance can review the plan in their own workbook with every line priced.
4. **Draft** (`stage draft`). `qz-bid-writer` writes the deck spec JSON and, if needed, the SOW content JSON (formats in `${CLAUDE_SKILL_DIR}/lanes/bid-formats.md`). Decks follow the `qz-deck-craft` skill: put audience, decision and minutes in the spec's `context`; agree the governing message and the slide titles with the person before drafting; 8-12 slides built from the kinds in `qz-demo-craft/references/deck-kinds.md`, every title a claim, every number with a `source`, speaker notes as the spoken narrative.
5. **Render** (`stage render`). `deck_build` (pass `plan`) and `sow_build` (pass `plan`). Rates reach a client document only as the rate of a role we priced for them, in the commercials table; the standard rate card never does, and the SOW builder removes the template's Rate Card section. Run `deck_review` with the spec and the `.pptx` (story, slide build, client voice) and `demo_check` on the deck (sparse slides, overflow, long titles); fix what they report and rebuild. Both builders run the client-voice check, which FAILs a rate card, any rate that is not a priced role's rate, and any internal pricing term; fix every FAIL and the WARNs that matter, then rebuild.
6. **Review** (`stage review`). `qz-reviewer` checks claims (done vs planned, numbers labelled), commitments to avoid, and the meeting prep: stakeholders, decisions, assumptions to validate, escalation risks, questions to ask, follow-ups. `qz-deck-rehearsal` plays the most sceptical decision-maker and returns the questions the deck does not survive; answer each on a slide, in a backup slide or in the notes, and write `meeting-prep.md` from `qz-deck-craft/references/meeting-prep.md` (internal only). Show the person the files and the review in one short list.
7. **Close.** `output_seal` the final deck, SOW and pricing client view; `report_card`.
