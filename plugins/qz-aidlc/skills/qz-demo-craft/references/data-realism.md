# Data that reads as real

A leader trusts a demo when the data looks like their own Monday morning. Rules:

- **Specific over round**: 41.7%, 1,284 suggestions, 11.2 h, 3 hours 20 minutes. Round numbers only for targets.
- **Units everywhere**: "% of merged lines", "idea → prod", "p50 · p85 26.4h", "°C", "per 1K lines".
- **Their nouns**: lanes, carriers, SOPs, claims, members, policies, wards, SKUs. Read the brief and their public site.
- **Owners and dates**: every document has an owning team and a review date; every event has a time; every run an id.
- **A mix of states**: mostly healthy, some amber, one red. A perfect board reads as fake. Include a stale document,
  a lagging source, a blocked action, a failing test that gets fixed, a question the system cannot answer.
- **Deltas with direction**: say whether up is good. Colour by goodness, not by sign.
- **Consistency**: the same number in two places is the same number. Compute derived numbers in code from one source.
- **Seeded variation**: use `QZ.series(seed, …)` so a presenter sees the same values in rehearsal and on the day.
- **Honest labels**: footers say "illustrative data" or "illustrative run" unless the data is real. Targets say "target".
- **Documents worth quoting**: 2-4 passages each, 2-3 sentences per passage, written the way a policy or SOP is written:
  numbered sections, thresholds, roles, time limits, exceptions. Include one superseded edition and one restricted
  document so governance has something to do.
- **Questions**: 4-5 the corpus answers well (one needing two documents) and 1 it cannot, phrased the way a busy
  person would ask.
- **No real people, no real client names** unless the person says so. Prefer role names ("the duty manager").
